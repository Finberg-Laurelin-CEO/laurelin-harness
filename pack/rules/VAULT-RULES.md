# Harness Rules (private half)

Template for the vault note `Laurelin/LaurelinOS/Harness Rules.md`. Copy this file there and fill each section. The public half is `pack/rules/laurelin.md` in the harness repo. Facts go here. Generic rules go there.

Headings only. Each line under a heading says what the section holds.

## 1. Canonical numbers

One table. Columns: quantity, value, unit, source document and revision, date set, who set it. Every number an agent may write into a deck, memo, email or preprint. Nothing else counts.

## 2. Numbers under dispute

Quantities that differ between two current sources, with both values, both sources, and the rule that picks one until Joe settles it.

## 3. Current articles and revisions

The current name and revision of each engineering article, drawing set and memo. The newest engineering document wins a conflict. Update this section when a revision is issued.

## 4. The company pitch

The order and the sentences Joe uses to describe the company. Link to the Style Guide note that holds them. Say which numbers in the pitch match the current deck and which do not.

## 5. Doctrines

One subsection per doctrine. Each gives the rule in one paragraph, the date it was set, who set it, and the vault note that holds the full text.

## 6. People rules

What may and may not be said about each named person in external material: advisors, former team members, investors. Each entry names the person, the rule, the date, and the note that explains it.

## 7. Classification and cryptonyms

Where the classification schema, the component table, the compartment register, the read-in roster and the cryptonym index live. Which outside parties hold which grants. The release test in words.

## 8. File locations

The real paths. Where each kind of output goes: per-investor decks, the general deck, superseded copies, memos, issued engineering documents, work logs, contracts, one-pagers. Which kit or pipeline builds each kind.

## 9. Model and vendor routing

Which data tiers may go to which models and vendors. Which vendors are approved for Yellow. What stays local for Red.

## 10. Change log

Dated lines. Newest first. Who changed what and why.
