Joe says the visual system "we use now" is what the skill must pull, so **LRL-DS is current** and the deck kit's system is legacy.
- The v8-NVS generator was built in a session scratchpad and has been copied to `~/laurelin-deck-kit/lrl-v8-rescued-20260925/` (`gen3.py`, `gen4.py`, `patch4.py`, `fixflex.py`, check PNGs, the PDF). It reads copy from `content/v8-copy.json`.
- The pipeline today: ground in the doctrine notes (Cote Rules win, then Non-Technical Deck Doctrine, then Deck Design; newest engineering source wins on figures; Joe's verbatim copy is untouchable) → edit `content/vN-copy.json` and `bin/build-vN.py`, never the HTML → build → `bin/copy-check.py` (dash rule hard fail, slop score), `fit-check.mjs`, `wrap-check.mjs`, `bin/qa-v7.mjs` (overlap, boundary) → look at every sheet as an image → ste-lint `--house --dict`, jev-sweep, humanizer → `export.mjs` to PDF, Ghostscript `/ebook` compress → file in `Laurelin/Investor Research/_circulating-decks/` (the real directory, never through the `investors` symlink), prepend the `> **Current vN:**` banner with pages, changes, slop score, SHA-256 to `_index.md`, move the old one to `_superseded/`, dated WORK-LOG → Joe's read-aloud pass → open in Acrobat, never Preview.
- Known drift: `~/laurelin-deck-kit/doctrine/` differs from the vault on six notes (`bin/sync-doctrine.sh --check`); `bin/deck-build.sh`, the kit's `CLAUDE.md` and its old `.claude/skills/deck-design/SKILL.md` still describe v4.

## Make
1. `pack/skills/deck-design/SKILL.md`: the method above as steps, with the tools per step and the prohibitions, and the conflict rule. It names the vault notes and the kit files by path. It states: LRL-DS is the current system; the kit's cream system is legacy and used only when Joe names an old deck.
2. `pack/skills/deck-design/style-pull.py`: reads `~/laurelin-visual-system/lrl.css`, `README.md` and `components/` at run time and writes `.laurelin/style.json` (tokens: colours, fonts, sizes, grid, image rules, logo rules, forbidden list) so a build always uses the live style, never a copy. `--print` shows it. No style values are committed to this repo.
3. `pack/skills/deck-design/build.py`: a generic builder derived from the rescued `gen4.py` and `patch4.py`: takes `--copy <json>` `--style <style.json>` `--out <html>`; layouts as named sheet types (title, stat cards, three-column, full-bleed art, chart, close, appendix); `.o60/.o40/.o25` hierarchy; one accent element per view; photos full colour with the 2 px rule and reticle corners; NDA-gated art only when the copy JSON marks the sheet `nda: true` and the run has `LAURELIN_NDA=1`. The rescued scripts are the reference; read them, do not copy Laurelin content out of them.
4. `pack/skills/deck-design/change.md`: how an aesthetic change Joe describes ("tighter top margin", "orange rule thinner", "move the ask to sheet 3") becomes a diff: Jev classifies the request (Choice: `style_token, layout, copy, order, art, delivery`); style and layout changes edit `style.json` overrides or the sheet type, never the copy; copy changes go through the verbatim gate; order changes edit the copy JSON's sheet list. Every change lands as a new version, never in place.
5. Gates wired: `layout.sh` (render every sheet, overlap and overflow), `numbers.sh` against the canonical file the task names, `prose.sh`, `verbatim.sh` on Joe's lines, `location.sh` with the real `_circulating-decks` directory as an allowed root, `evidence.sh` for the built PDF. Add a `deck.sh` gate that checks: page count matches the copy JSON, sheet numbers are sequential, no grayscale image, PDF under 5 MB after compression, filed path is the real directory not the symlink, and the `_index.md` banner has pages, SHA-256 and the build command.
6. `pack/skills/deck-design/register.py`: appends a machine-readable row to `_circulating-decks/versions.jsonl` (version, date, pages, sha256, path, changes) beside the human banner, so versions are a register not free text. Writes only under `--apply`; prints otherwise.
7. Doctrine sync check: the skill's first step runs `bin/sync-doctrine.sh --check` in the kit and refuses to build on drift until Joe runs the sync (the skill never writes the kit's doctrine folder).

## Test
`tests/test-deck-design.sh`: `style-pull.py --print` reads the live visual system and reports tokens (skips if the folder is absent); `build.py` on `tests/fixtures/deck/sample-copy.json` (invented company, invented numbers, three sheets, no art) produces an HTML with three sheets; `export.mjs`-style render through the kit's exporter if present else `pdftoppm` on a printed PDF, then `layout.sh` passes on it and fails on a fixture with an overlapping label; `deck.sh` passes on the sample and fails on a copy with a sheet count mismatch and on a grayscale image; `register.py` prints a row and writes nothing without `--apply`; the change classifier labels "make the orange rule thinner" as `style_token` and "change the ask to $4M" as `copy` (skips without the Jev key). Never reads `content/v8-copy.json` or the vault.
